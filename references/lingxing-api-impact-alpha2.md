# 领星 API 数据来源与影响清单

整理日期：2026-10-29。代码版本：`v0.2.0-alpha.2`（`56a8ccf`）。本说明依据当前适配器、库存计算、面板渲染及已保存的真实查询审计核对；本次整理没有重新调用外部接口、重新计费或修改业务数据。南斗实施方案仍待用户审核，不启动接入。

## 1. 接了哪些接口

本批新增四类接口，沿用 alpha.1 的两个来源/发货单接口，累计六个。全部是只读查询；HTTP POST 不代表创建或修改业务单据。

| 类别 | 完整接口路径 | 读取的数据 | 接入批次 | 本次真实验收适配器查询数 |
|---|---|---|---|---:|
| ASIN 在途来源 | `/erp/sc/routing/fbaSug/asin/getSourceList` | 店铺+ASIN 的 FBA 来源货件号、来源数量 | alpha.1 沿用 | 52 |
| 发货单 | `/erp/sc/routing/storage/shipment/getInboundShipmentList` | 发货单号、状态、货件/店铺/ASIN 关联、`expected_arrival_date` | alpha.1 接入，alpha.2 修正状态/分页/关联 | 53 |
| FBA 货件内容 | `/erp/sc/data/fba_report/shipmentList` | ASIN/SKU/MSKU/FNSKU、状态、申报量、本地实发量、FBA 已收量、每箱数量 | alpha.2 新增 | 1 |
| 本地产品 | `/erp/sc/routing/data/local_inventory/productInfo` | `cg_box_pcs` 箱规；supplier_quote/quotes/step_prices 的报价 MOQ；官方组合产品关系 | alpha.2 新增 | 102 |
| 采购订单 | `/erp/sc/routing/data/local_inventory/purchaseOrderList` | 行店铺/SKU、订单/到货/删除状态、采购量、待到货余额、入库量、退换货量、预计到自有仓日期、订单箱规 | alpha.2 新增 | 13 |
| 实际采购收货 | `/erp/sc/routing/deliveryReceipt/PurchaseReceiptOrder/getOrderList` | 行 `seller_id`、`product_receive_num`、头部 `receive_time`、采购单和采购行引用、原预计日期 | alpha.2 新增 | 15 |

合计 236 次适配器查询，均为成功业务码。该数字不包含签名客户端内部的传输重试，也不是 SIF 配额。采购/收货接口分页响应可能包含更多店铺，适配器逐行过滤后仅保留当前两个授权店铺。

四类明细结果：102 个 SKU 产品规则、320 行 FBA 内容、581 行采购、412 行实际收货。货件来源/发货单涉及 52 个商品、144 条商品货件关系。行数不是单据张数或货件唯一数。

## 2. 各类数据影响了什么

| 来源 | 接入的原始字段 → 项目字段 | 直接影响 | 计算边界 |
|---|---|---|---|
| 来源+发货单 | `remark.shipment_id`、`quantity`、`shipment_sn`、`relate_list`、`expected_arrival_date` → `supplyEvidence`、`inbound`、`etaReconciliation` | ASIN 到 FBA 货件/发货单关联；预计到 FBA 仓日期；确认/未知在途、库存时间线、断货恢复判断、库存风险和证据 | 预计到 FBA 仓不是预计可售；不使用港口 ETA。缺失/过期/多单歧义不会自动补日期 |
| FBA 明细 | `quantity_shipped`、`quantity_shipped_local`、`quantity_received`、`quantity_in_case` → `fbaShipmentEvidence` 及数量核验 | 面板分列申报/本地实发/FBA 已收；修正待拣货/待发货/完成状态，限制可确认到货量 | 实发减已收与来源量交叉核对，并受当前 MCP 实时在途上限约束；申报不当成实发；待发/完成不计未来供给。货件每箱量保留为事实，不替代产品标准箱规 |
| 产品规则 | `cg_box_pcs` → `cartonQty`；报价阶梯 → `moq`；组合关系 → `product_rules.components` | 缺省箱规/MOQ、建议发货/采购批量、整箱取整和箱数；组件关联明细展示 | 保留手工有效参数；报价最低阶梯一致且大于零才补默认 MOQ；零值/缺失/歧义不强填；组件不是成品库存，未做齐套求解 |
| 采购订单 | `quantity_real/receive/entry/return/exchange`、`expect_arrive_time`、行 `sid` → `purchaseEvidence`、`procurementOpen`、`procurementLots` | 店铺采购单明细、窗口内有效未结、预计自有仓日期、本地供给参考/缺口、采购齐套参考、诊断 | 待到货含尚未发货；关闭/作废/未下单排除，退换货或数量冲突待核对；国内到库日期不能充当 FBA 恢复日 |
| 实际收货 | `product_receive_num`、`receive_time`、`seller_id`、`business_order_sn + order_item_id` → 收货台账及采购 `actual_received_in_window/actual_times` | 店铺级实际数量和完整时间；核验采购余额；区分实际与预计；展示组件收货 | 关联后再核对店铺/SKU；不从“采购量减本窗口收货”猜全历史未结；不把收货再次加进现有库存；时间/数量异常保持待核对 |

箱规/MOQ 的数值只来自产品规则；采购单箱规与 FBA 货件每箱量分别保留，不能混用。产品接口刷新失败时，旧 API 默认值失效，手工配置不受影响。

## 3. 需要特别注意的口径变化

**采购未结已发生来源切换。** 原 MCP 参考值保留在 `procurementMcpReference`，当前 `procurementOpen` 使用 API 查询窗口内、精确店铺/SKU 的余额。一个 SKU 对应多个 ASIN 或余额异常时保留 null，界面显示“待核对”，不按销量分摊。

原库存引擎对该未知量在供给求和时按零贡献处理，这是保守测算，不是认定真实未结为零。因此它可能降低本地参考供给、提高参考缺口或改变诊断，必须连同“窗口内/待核对”说明理解。现有采购建议仍保留原保守策略：本地、海外和采购未结只作参考，不直接抵扣建议采购量；不能宣称本批已实现“用完整采购在途自动去重所有建议采购”。

**实际收货不增加当前库存。** 当前库存已由领星 MCP 提供，再把实际收货或采购入库累加，会对同一批货重复计量。已关闭采购即使保留未来预计到库日，有效未结仍为零。

**预计自有仓与预计 FBA 仓分开。** 采购单预计日期用于国内采购参考；发货单 `expected_arrival_date` 用于 FBA 到仓证据。没有可靠 FBA 日期的货件不推迟断货日；API 到仓时间不是可售时间保证。

## 4. 当前真实面板的变化量

以下是同一数据日、同一运行批次、171 个商品的 alpha.1 候选与 alpha.2 候选逐字段对照。统计“对象/数组内容有变化的商品数”，不是改动单据数，也不等于每项变化都由一个接口单独造成。

| 项目 | 变化商品数 | 解释 |
|---|---:|---|
| 库存风险等级 | 6 | 依更新后的供给/计划证据重算 |
| 原库存时间线 | 2 | FBA 关联、状态、实发量和 ETA 核验影响 |
| 建议发货批次 | 52 | 包括箱规/MOQ和供给证据引起的数量、日期或批次字段变化 |
| 建议采购批次 | 48 | 箱规/MOQ等进入原滚动补货逻辑；并非采购未结直接抵扣 |
| 本地参考供给 | 20 | 窗口内采购余额替换原参考值后的数值变化 |
| 本地参考缺口 | 38 | 供给与批量目标共同变化 |
| 本地目标量 | 48 | 计划批量变化传导 |
| 库存结论对象 | 60 | 包含结论文案/数量/计划的变化，不全等于风险升级 |
| 需求预测 | 0 | 销量与预测数据保持一致 |
| 冗余判断对象 | 0 | 本次对照没有变化 |

相对于原 MCP 库存输入，59 个商品补入有效 API 箱规，41 个补入有效 MOQ；采购未结字段有 93 个商品变化，其中包括原数值变未知。最终 12 个商品有正的窗口内未结，76 个因共享 SKU/多 SKU 或核验等条件保留未知；这不是 76 次 API 失败。

实际可查看证据：76 个商品关联 FBA 明细、21 个关联直接 SKU 采购、70 个关联直接 SKU 或组件的实际收货。这些是展示引用覆盖率，同一单据可能被多个商品引用，不能相加做总量。

原 FBA 可售、预留、接收中、实时在途、本地/海外现货数量未被这批 API 写入替换。所有非库存商品字段逐项一致，包括 SIF 关键词、排名、广告、销售历史与原动作数据；库存问题重排可能影响综合问题列表顺序。原 `run_id` 和来源日期不升级为新的广告或 SIF 数据批次。

## 5. 真实样本与保留的缺口

- 两票货件各申报 504 件，已关联发货单，但本地实发为 0、待拣货、ETA 空：可展示关联，不算确认在途。
- 一笔实际收货 200 件、另一采购单四行各 1,500 件，实际时间已在 10 月发生；采购仍有 11 月预计日期，但关闭后的未来供给为零。
- 581 行采购：144 行余额可核验、431 行关闭、5 行未下单、1 行数量/换货异常待核对。412 行收货：411 行关联本窗口采购，1 行来自窗口外采购。
- 77 条货件关系 ETA 过期，24 条缺日期，7 条实发量待核对。最终只有 1 个商品具备符合规则的未来确认到仓证据，不能因接口成功就补成“全部 ETA 已完善”。
- 窗口为 2026-01-01 至 2026-10-29：采购按创建日期，收货按实际收货日期，FBA 按创建日期；是窗口内完整分页，不是全历史余额。API 通用增量/跨运行缓存仍待后续建设。

## 6. 尚未接入的数据及展示位置

`/erp/sc/routing/storage/inbound/getOrders` 系统入库明细接口尚未接入。当前保留的 `quantity_entry` 来自采购订单，不是独立入库单、实际收货时间或系统操作时间。原契约把这个接口放在“已接入”表中会误导，本次文档已纠正。

查看位置：商品面板的 **采购台账 → 领星 API 实际单据与产品规则** 折叠区，包含产品规则、店铺采购、实际收货、FBA 货件和到仓日期。其下方“建议采购”仍是原引擎测算，不能与上方真实采购单相加。

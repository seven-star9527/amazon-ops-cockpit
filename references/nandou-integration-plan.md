# 亚马逊运营应用与 Agent 接入实施计划

本计划按当前南斗工作树只读核查制定；本批没有修改、运行或发布南斗。建议形态是 **运营应用 + 专属 Agent + 可复用技能**：应用承载面板与人工操作，Agent负责解释、任务和受控执行，技能保留已有采集/诊断能力。无需把整个应用塞进提示词，也无需重建一套Agent平台。

## 已完成与仍未实现

- 已完成：只读底座、依赖隔离、外置数据、SIF缓存与失败续跑、缺失值修复、Git基线；本批开始API只读适配和同日库存快照补充。
- 尚未完成：完整API数据接入、组织权限服务、应用分类与页面入口、Agent上下文桥接、个人面板配置、运营回填执行、定时刷新通知。后文均为实施清单，不是现有功能声明。
- 原有面板布局、诊断与补货计算优先复用；权限、执行边界不得靠前端隐藏按钮实现。

## 数据与权限模型

运营有效范围 = 当前本人领星MCP有权店铺 ∩ 组织允许店铺。主管范围 = 本人领星MCP有权店铺 ∩ 所辖部门运营的店铺并集 ∩ 组织允许店铺。组织管理员具备组织管理角色，还需具备对应领星数据读取授权；缺少授权时显示覆盖缺口，不能借企业API凭据自动绕过。

同一店铺可分配多人，主管汇总按店铺+业务主键去重。部门调整、离职、撤销连接后，服务端权限版本失效，缓存、导出下载和Agent历史引用重新校验。页面筛选、传入sid、旧snapshot_id都不能扩权。原始采购单跨店铺行必须逐行授权；无归属行进入组织级受限未分配池，不进个人面板。

领星MCP共享的是连接器定义，每位运营/主管绑定自己的密钥。领星OpenAPI是独立的企业应用凭据，仅在服务端代查经过权限裁剪的数据。SIF和卖家精灵分别使用组织共享凭据/额度池；建立供应商独立预算、统一限流、任务预留与实际用量账本。可共享的公共ASIN市场事实与私有经营指标分库存放，共享缓存不会赋予店铺读取权。

本项目本地运行数据保存在外置数据目录；南斗运行时，组织事实、配置、任务与审计保存到服务端数据库，原始大响应和不可变快照保存到带组织权限的文件/对象存储。本机只保留可清理缓存。不得保存到技能安装目录，亦不能把开发机盘符作为所有用户的共享路径。

逻辑实体尽量合并到现有表：数据批次/任务、规范化事实、面板配置、执行草稿、执行回执。每条记录至少带组织、来源、业务主键、数据日期/采集时间、权限版本；只有个人配置另带owner。不要为每次Agent对话复制全量经营数据。

P1b与P2可独立准备；权限完成前不把本机静态服务暴露为组织应用。应用入口只完成P4不能宣称企业运营平台完成。

## 个人面板与母版

母版包含受版本控制的组件清单、字段类型、默认规则和数据绑定。个人配置是基于母版版本的差异，手工与Agent调用同一配置API，带revision做乐观锁。保存前做schema校验与差异预览，保留上一版可撤销。母版升级通过迁移器与冲突提示合并，不让每个人维护一份HTML源码副本。

布局、隐藏字段、图表类型和主题属于展示；诊断阈值/补货参数属于个人规则并注明来源；供应商原始数据属于事实，不能被参数覆盖。新增板块采用受限组件/表达式和允许的数据集；不允许Agent注入任意JS、SQL、网络调用或重写权限校验。主管查看的是经授权的运营面板和汇总事实，不能顺带获得修改个人规则或执行业务操作的权限。

## 回填与执行

保留现有场景、审核和广告操作模型，新增必要的版本/范围/幂等保护，不另造重复工作流。回填记录是显式业务输入，带操作者、来源快照、变更前后值；Agent可读取并生成草稿，回填本身不是执行授权。母版、权限规则和允许执行的工具白名单统一管理。执行工具默认不挂载到只读Agent；确认后才发放限定对象、限定动作和短期有效的执行授权。

当前旧执行代码仍需专项加固：完整检查批次与快照时效、操作前值与授权范围，不能把“调用未抛异常”当成业务成功；递归检查供应商业务码并执行读回。任何结果未知先对账，不能再次提交同一操作。广告写回、采购写回、通知发送分别验证，不相互替代授权。

## 下一批最小交付

先完成P1b中的货件明细和箱规/供应商MOQ，再完成采购实际收货链。采用每源一个可审查提交和真实只读验收，稳定后才迁入服务。南斗开工时先P2/P3，随后P4只读应用；个人化和执行分开迭代。共享额度调度最后启用，避免用自动化放大未解决的数据或权限问题。

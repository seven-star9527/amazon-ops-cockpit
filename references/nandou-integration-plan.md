## 三、连接、数据和权限约定

### 3.1 官方连接与个人身份

组织共享供应商官方连接器定义。实施时从官方文档核对 endpoint、认证 header、只读工具 schema、限流和计费单位，记录日期/版本；不从第三方代理或员工配置复制身份。沿用 N7 的共享审核、绑定版本和撤销机制。

| 来源 | 凭据模式与执行位置 | 用途与约束 |
|---|---|---|
| 领星 MCP | `credential_mode=member`；运营/主管分别填写本人 Key | 本人有权店铺与经营数据。运营集成建议先用 server_proxy，后端可信查询范围；如保留个人 client_direct，仍需服务端按本人凭据单独校验，不能信任客户端声明。网络不通明确失败，不借企业 API 或管理员身份绕过 |
| 领星 OpenAPI | 企业应用凭据仅存服务端，复用签名/token 客户端 | 四类补充数据。每次读/导出/Agent 引用均按有效店铺过滤；企业凭据范围大不代表员工权限大；跨店采购单逐行裁剪 |
| SIF MCP | `credential_mode=organization` + `server_proxy` | 统一配额入口、缓存、限流与只读白名单，共享 Key 不下发个人设备 |
| 卖家精灵 MCP | 同上，但独立供应商账本/预算 | 不混用供应商计费单位；同一额度账户由多个连接引用时归并同一池 |

N7 `_effective` 限制本人私人 Agent，复用这一边界；不能让所有人共用一个执行身份。未来后台任务显式绑定 owner 和授权宿主，不伪装管理员或随意改用群 Agent。端点/凭据实际配置仍待接入时验收，本次未修改任何连接器。

### 3.2 店铺与部门权限

- 运营：本人领星有权店铺 ∩ 组织允许店铺。
- 主管：本人领星有权店铺 ∩ 所管部门运营店铺并集 ∩ 组织允许店铺。子部门沿用 include_descendants。
- 管理员：组织运营店铺并集 ∩ 本人领星有权店铺 ∩ 组织允许店铺。要看全部，需在领星给本人相应权限；缺少时显示覆盖缺口，不借企业 API 扩权。
- 主管查看员工面板时按访问者权限裁剪；owner 决定布局/参数，不决定访问者权限。查看权不附带修改个人配置或执行业务的权限；私人对话不因主管看面板而公开。
- 调部门、离职、撤销 Key、定义变更、领星授权变化均更新权限版本；同步失败不延长旧授权有效期。短期范围过期时拒绝新读取并隐藏旧敏感内容；已合法导出的离线文件无法远程收回。
- 同店多人负责，汇总按店铺/事实主键去重，不相加个人面板总数。无店铺归属行不进个人面板，进入受限质量清单。

### 3.3 存储、重复运行与新鲜度

本地继续外置 `AMAZON_OPS_DATA_DIR`/`--data-dir`，venv 与代码分离。南斗采用独立 Python worker/服务，不把依赖装进 Django 或 Agent 环境。Node 计算复用现有引擎，worker、依赖锁和项目版本一起固定。

组织事实及不可变批次放受组织权限控制的服务端存储；批次/当前指针/任务/配置/审计元数据复用 PostgreSQL 和现有存储。只补必要业务字段/表，不按用户或聊天复制全库。个人配置、回填与经营事实分开，技能安装目录不写数据；未裁剪企业原始响应仅受限采集服务可读。

批次保存来源、查询窗口、源日期/采集时间、店铺授权版本、schema/规则版本和质量状态。“打开面板”不是“数据已更新”。全部校验成功后切换单一当前指针，中途失败/撤权不发布半套结果。历史快照读取同样检查当前权限。

采购、收货按供应商业务行主键，FBA 按店铺/货件/明细主键去重；不同来源不可只凭 SKU 盲合并。API 端点有可靠更新时间才使用水位，否则用重叠窗口、未结单复查和周期性对账；失败不推进水位，关闭/取消/退换货不能漏。当前采购创建时间窗口外的收货引用，按采购单引用补查，不必扩大所有人的全量窗口。

SIF 不承诺供应商有增量接口。复用现有筛选、缓存、失败冷却：以组织额度账户/市场/ASIN/工具/标准化参数/源周期/schema 为键；历史已完成周期长缓存，当前周期按新鲜度刷新。空结果与失败分开，只补失效、失败或缺失项；含私有经营指标的结果不能作为公共 ASIN 缓存共享。

### 3.4 面板与 Agent 契约

南斗认证决定 organization_id、actor_id 和权限；面板提交 dashboard_id、snapshot_id、sid、asin、筛选与 config_revision 等待访问对象。Agent 携带引用与必要摘要，不携带全量 HTML、Key 或凭据 ID。工具服务重新校验引用/权限，模型传入的 sid 只是请求。

首批只提供读看板/事实、查刷新状态、明确预算内的只读刷新；刷新消耗额度也需闸门。后续分别增加配置预览/保存、回填读取/保存、执行草稿和确认。页面与 Agent 调同一业务 API，避免双重计算口径。

嵌入页到宿主只开放明确消息类型，校验 origin、view、组织、用户及一次性上下文标识，不允许任意 IPC/脚本/工具名透传。采用短时、应用专用认证引导，不将南斗长期 token 或供应商 Key 放进 URL、HTML、localStorage。退出、切组织和撤权清空旧上下文。

| 发布 | 计算/渲染失败、发布中断、中途撤权、并发刷新 | 当前指针只指完整有效批次；失败有状态；不覆盖个人配置/回填 |
| 页面/Agent | 商品切换立即询问、切组织、重开、有草稿、重复点应用、浮层遮挡 | 不串会话/店铺；标签和服务数稳定；原关键词/排名/采购图表有读回证据 |
| 配置/执行 | 修改布局回滚、母版升级冲突、重复确认、回执未知 | 母版不覆盖；配置不能改权限；同动作幂等；未知进入对账，不自动再次提交 |

每包交付差异、针对性测试、真实读回证据、依赖/迁移/回滚说明与未覆盖项。业务原始明细、密钥、截图留受控目录，仓库只放脱敏记录。节约额度/性能结论需同范围实测请求数对照，不能以“有缓存”替代验收。

## 六、个人配置与统一管理

个人差异基于母版版本，手工与 Agent 共用 schema、预览、revision 保存与撤销。展示配置和诊断/补货参数分层；供应商事实不可被参数覆盖。新板块限已审查组件/授权数据绑定，禁止任意脚本/网络调用。主管默认只看；母版、权限和允许执行的工具白名单由组织管理。

回填记录保留操作者、来源快照、前后值、时间和版本。Agent 可读并生成建议，外部执行须另经确认与动作授权。不能直接启用本地可写审核服务作为企业后端，现有执行代码须完成 I7 才能开放。

## 七、首期范围和运行生命周期

下一阶段先 I0–I3，再交付 I4/I5：组织安装应用、个人绑定领星、共享额度可控、原看板可用、专属 Agent 只读交互。个人定制、业务执行、定时通知分别验收，不混成一次发布。

本地更新复用已确认归属/目录的健康服务，先校验候选 HTML 再替换，不必每次另起随机端口。换目录/进程时登记 PID、端口、目录、版本，确认新服务后结束精确匹配旧进程，不按端口猜测杀进程。当前启动器默认 8769，`--port 0` 是显式要求随机端口；尚无自动发现/回收服务的完整管理器。南斗复用应用标签和进程托管，避免每开一个 Agent 就启动一套面板。
